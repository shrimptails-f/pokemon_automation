# Arduino Micro の書き込み

対象スケッチ、ソースのコミットと未コミット変更、接続環境を確認し、リポジトリの該当 README や `docs/windows-arduino-upload.md`、診断固有の文書に従う。ユーザーが示した WSL パスや COM ポートを例として引き継ぎ、未確認のポートは明示する。Arduino 書き込みポートと SH-U09C 通信用ポートを区別する。

ユーザーが 1 コマンドでの書き込みを望む場合、リポジトリ配下の PowerShell スクリプトにポート検出、固有の一時ビルドディレクトリ、`arduino-cli compile` と成功後の `arduino-cli upload` をまとめ、そのスクリプトを実行する 1 コマンドを示す。適切な既存スクリプトがあれば確認して再利用する。書き込みと診断プログラムの実行は分け、書き込みスクリプトから診断を自動実行しない。診断スケッチは必要なファイルを確認してコピーする。通常の Switch 用ファームウェアはスケッチディレクトリ全体をコピーし、リポジトリの手順にある USB VID・PID・製品名・メーカー名と extra flags を付けてコンパイルする。診断専用スケッチと通常ファームウェアを混同しない。

実機に PC 側ツールを接続する場合はファームウェアと同じコミットを使う。既存作業に未コミット変更があればそのまま保護し、必要に応じて独立 worktree を用意する。書き込み後のポート変更は環境によって起こるため、失敗時は `arduino-cli board list` やブートローダーの手順を案内する。実行結果は確認できた範囲だけ報告する。

ポートは可能なら `serial.tools.list_ports` や `arduino-cli board list` の出力から識別情報を使って検出し、Arduino と SH-U09C を混同しない。一意に特定できなければ候補を表示して停止する。書き込み後に Arduino のポートが変わる場合は再検出する。Switch 向けファームウェアの `0F0D:0092` は他の機器でも使われうるため、その識別子だけで対象を確定できない環境では誤書き込みを避ける。
