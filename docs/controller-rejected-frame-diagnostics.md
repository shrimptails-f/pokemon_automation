# CRC 不一致の受信内容を採取する

通常ファームウェアが CRC 不一致として破棄した行を保存し、PC が送ろうとした内容と比較する。通信速度は 115200 bps のまま、操作を伴わない `STATUS`・`DIAG`・`DUMP` を使う。周回プログラムなど、同じポートを使うアプリケーションは終了してから実行する。

## 保存する範囲

- 改行まで受信でき、CRC 欄が4桁の大文字16進数として読めたが、本文の CRC と一致しなかった直近1行を保存する。
- 保存するのは行の組み立て処理が `2,` から取り込んだバイト列。終端 LF は含めず、CRC とその前のカンマ、埋め込まれた NUL 等はそのまま残す。先頭ノイズとして既に破棄したバイトは含めない。
- 長さは受信時の値を使い、最大159バイト。解析による書き換え前に保存する。記録が複数発生すると古いものは上書きされる。
- 形式不正・途中行の期限切れ・長さ超過は従来のカウンターだけで確認する。今回は CRC 不一致の原文保存に絞る。
- 記録番号は起動時0（記録なし）から増加する。`4294967295` に達した場合は最後の記録を固定し、同じ番号で内容を更新しない。電源断・再起動で記録は消える。読み出し中に電源を入れ直さない。

`DUMP` はセッション確立やボタン操作、リース更新を行わない。要求の CRC・形式検査と応答フレームへの再応答防止は従来どおり行う。

## 読み出しプロトコル

通常と同じ CRC 付きフレームを使用する。

```text
要求: 2,セッション,要求番号,DUMP,記録番号,オフセット,CRC\n
応答: 2,セッション,要求番号,DUMP,記録番号:全長:オフセット:HEX,CRC\n
```

- 最初は記録番号0・オフセット0で最新記録を取得する。続きは返された記録番号と取得済みバイト数を指定する。
- 1応答につき最大32バイトを大文字16進で返す。各応答は最大160バイトのプロトコル制限内に収める。
- 記録なしは `NONE`、番号が変わった場合は `STALE`、範囲外は `RANGE`、数値が不正な場合は `VALUE` を結果欄に返す。
- PC は番号・全長・位置・分割長を検査する。`STALE` なら途中のデータを捨てて先頭から最大3回取り直す。各読み出し要求は同じ要求を最大3回送信する。取得不能は成功として扱わずログと画面に残す。
- 通信断後に再起動して同じ番号が再利用されたケースは、番号だけでは検出できない。新しい電源投入ごとにテストも開始し直す。

## Windows での実行

PC 側とファームウェアは同じコミットのものを使う。未コミット変更を含む別の作業ディレクトリからコピーすると、ビルドや診断形式が変わるため、対象ブランチの独立したチェックアウトまたはソースの ZIP 展開先を使う。

まず対象ソースを `$repo` に指定する。以下は Windows のソース展開先が `C:\work\pokemon-issue12` の例。

```powershell
$repo = 'C:\work\pokemon-issue12'
$run = Join-Path $env:TEMP ('controller-diag-' + [guid]::NewGuid())
$sketch = Join-Path $run 'switch_arduino_micro'
$build = Join-Path $run 'build'
New-Item -ItemType Directory -Path $sketch, $build -Force | Out-Null
Copy-Item -Recurse -Force "$repo\controller\switch_arduino_micro\*" $sketch
arduino-cli board list
arduino-cli compile --fqbn arduino:avr:micro --build-property 'build.vid=0x0F0D' --build-property 'build.pid=0x0092' --build-property 'build.usb_product=\"POKKEN\040CONTROLLER\"' --build-property 'build.usb_manufacturer=\"HORI\040CO.,LTD.\"' --build-property 'build.extra_flags={build.usb_flags}' --output-dir "$build" "$sketch"
```

コンパイル成功を確認してから、実測した Arduino のポートへ書き込む。`COM7` は例であり、SH-U09C のポートではない。

```powershell
arduino-cli upload --fqbn arduino:avr:micro --port COM7 --input-dir "$build" "$sketch"
```

元の接続に戻し、SH-U09C のポートで実行する。以下の `COM8` も実際のポートに合わせる。`pyserial` が未導入なら `python -m pip install pyserial` で導入する。

```powershell
$log = Join-Path $run 'serial.jsonl'
python "$repo\tools\controller_single_request_test.py" COM8 --rounds 100 --log "$log"
```

- 接続初期化時だけ改行を送る。各要求や再送の前には改行を追加せず、先頭混入の症状を隠さない。
- 各回の前後に `DIAG`、間に再送なしの `STATUS` を送る。比較に使う `DIAG` も再送しない。`STATUS` の結果は後続の診断が失敗しても残る。
- CRC カウンター増加を初めに検出した場合、前後比較で破棄数が増えた場合、または要求がタイムアウトした場合は、保存記録の取得を試す。
- `DIAG` の失敗でカウンター比較ができなくなっても、記録取得を試みてから終了する。保存内容が読み出せない場合でもそれまでの送受信ログは残る。
- 全ての送信試行、書き込み結果、受信した生データ（空読みも含む）、再送、時刻（UTCと単調増加時計）、診断結果を JSONL に逐次 flush する。`tx` は送信しようとした値であり、Arduinoへの到達を保証しない。`rx` は `readline()` が返した単位で、1行とは限らない。
- 同名ログへの上書きはしない。再試験は新しい `--log` を指定するか、省略して時刻付きファイルを作る。通信中のプロセス終了でも flush 済みの行が残るが、OSや電源障害への永続化保証ではない。

## 結果の読み方

保存内容を直近256送信の履歴と比較し、類似する上位3種類の候補を表示する。全送信履歴は JSONL に残るが、古い送信は自動比較の対象外になる。再送された同一バイト列は表示上まとめる。位置は0始まりで、終端LFを除いた内容を比較する。

`変化`・`欠落`・`混入` は候補との編集差分であり、同じ文字が続く箇所などでは位置が一意に決まらないことがある。類似度が高くても、その候補が対応する要求だという証明にはならない。電気的な問題、受信取りこぼし、メモリ破損などの原因も差分だけで断定しない。

同じ給電・配線・速度で数件採取し、ログと接続条件、ファームウェアのコミットを残す。速度変更などの比較試験は採取結果を見てから条件を一つずつ変える。

## メモリと検証範囲

Arduino AVR core 1.8.8、Switch 向けビルドで静的RAMは1203 / 2560バイト（46%）、Flashは13636 / 28672バイト。静的領域以外の1357バイトはスタックや動的確保にも使われる。直近5件の応答を保存するローカル診断機能はこのブランチには含めない。スタックには既存のコマンド解析・応答用バッファもあるため、残量をすべて追加バッファへ使えるとは考えない。

ホスト上の回帰テストとビルドは実機の割り込み、電気的状態、長時間動作を保証しない。実機での不一致採取と RAM の動作余裕の確認は残課題。
