# コントローラー通信プロトコルの信頼性設計

本書は実装予定の設計方針を示す。現行プロトコルに以下の仕組みは未実装である。

## 前提・対象範囲

```text
PC ── USB ── SH-U09C ── UART ── Arduino Micro ── USB ── Switch
```

- PC は SH-U09C と Arduino を一つの操作サブシステムとして扱う。対象は PC ↔ Arduino の命令・結果通信と Arduino 側の操作管理。
- 通信は Arduino の `Serial1` を使う 115200 bps のシリアル通信。改行区切りのテキスト形式を継続する。
- 配線・電圧設定は [配線・接続手順](../controller/switch_arduino_micro/README.md#sh-u09c-と-arduino-の配線)、書き込みは [Windows からの書き込み手順](windows-arduino-upload.md) を参照する。
- [現行ファームウェア](../controller/switch_arduino_micro/switch_arduino_micro.ino) は `PING/PONG`、操作名と `OK/ERR` を使用する。通常のボタン押下時間は150ms。新方式では PC が時間を指定し、既存操作の初期値は150msを引き継ぐ。
- Arduino の処理完了と Switch 上での操作反映は別の判定とする。ゲーム状態の確認はキャプチャー画像などを使う上位の処理が担当する。

## 目的

通信の破損・欠落・切断により、命令や応答が届かない場合がある。特に操作後の応答だけが失われると、PC は実行の有無を判別できず、単純な再送は二重操作につながる。Arduino の再起動では実行履歴も失われる。

壊れた命令の実行を防ぎ、一時的な障害には安全に再送できるようにする。結果を確定できない場合は周回を停止し、不明な状態のまま次の操作へ進めない。物理的な通信不良の原因調査・修復は別途必要であり、本設計で代替しない。

## 信頼性設計

### メッセージの検証

要求・応答にセッションID、命令番号、CRCを付ける。要求には操作と引数、応答には処理状態と必要に応じたエラー理由を含める。以下は概念例であり、CRC値は省略している。

```text
CMD,<session>,42,PRESS,A,150,<CRC>\n
RESULT,<session>,42,DONE,<CRC>\n
```

Arduino は長さ、CRC、命令、引数を検証してから実行する。途中で切れた行には受信期限を設け、長すぎる行とともに破棄して改行境界に再同期する。破棄した断片を新しい命令として実行しない。PC も応答のCRCとセッション・番号を照合し、対応しない応答で完了扱いにしない。

CRC不一致などで番号自体を信用できない要求は実行せず破棄する。整合性を確認できた要求の引数不正などは、対応する番号で拒否理由を返す。CRCは偶発的な破損検出用であり、すべての破損を検出する保証や認証機能ではない。

### 実行と完了の定義

同時に処理する操作命令は1件とし、PC は正常な完了応答を受け取るまで次の操作を送らない。

1. 検証済みの命令番号・内容を実行中として記録する。
2. 対象ボタンを押した状態のUSBレポートを送信する。
3. Arduino が指定の押下時間を管理する。
4. 対象ボタンだけを解放したUSBレポートを送信する。他のボタンの状態は維持する。
5. 完了を記録してから `DONE` を返す。

`DONE` は Arduino 側で対象操作の解放まで所定の処理が完了したことを表し、Switch の画面変化は保証しない。押下・解放ともUSBライブラリが提供する送信結果を確認する。キュー登録までしか確認できない場合は保証範囲もそこまでとし、送信関数の呼び出しだけで Switch の受信成功とみなさない。利用ライブラリの保証範囲と必要な変更は実装前に確認する。

| 結果 | 意味・扱い |
| --- | --- |
| 完了（`DONE`） | 定義した処理が完了し、PC が対応する正常応答を受信した |
| 拒否（`REJECTED`） | 検証済みの要求を実行前に拒否した。操作は行っていない |
| 処理中（`IN_PROGRESS`） | 実行中であり、完了ではない |
| 結果不明（`UNKNOWN` または PC 側の判定） | 操作開始後の異常や有効な最終応答の欠落などで、結果を確定できない |

操作開始後のUSB送信失敗などは未実行の拒否と区別し、解放を試みて結果不明を返す。タイムアウトも未実行の証拠とは扱わない。

### 再送と重複排除

PC は応答待ち期限を超えた場合、同じセッション・番号・内容で再送する。Arduino は現在または直近の命令内容・状態・結果と、受け付けた番号を保持する。

| 受信した命令 | Arduino の動作 |
| --- | --- |
| 次の番号の正常な命令 | 前の命令が完了していれば一度だけ実行する |
| 同じ番号・内容の命令 | 実行中ならその状態を、終了済みなら保存した結果を返す。再実行しない |
| 同じ番号で内容が異なる命令 | 拒否する |
| 古い番号、番号の飛び越し、処理中の別命令 | 実行せず拒否する |

完了応答が失われても、同一命令の再送でボタン操作を繰り返さない。結果不明になった命令も再実行せず、その状態を保持する。実行中にも受信処理できるよう、押下時間の管理で通信処理をブロックしない。

再送回数と操作全体の待ち時間に上限を設け、処理中の応答が続いても無期限に待たない。完了を確定できなければ周回を停止する。

### セッションと再起動

接続時にセッションを確立する。Arduino は起動直後には有効なセッションを持たず、確立前の操作や異なるセッションの操作を拒否する。

同じセッションと実行履歴が残っていることを確認できれば、再接続後も同一命令の結果を問い合わせ・再送できる。再起動などで履歴を失っていた場合、未確定の操作を新しいセッションで自動再実行しない。PC は周回を停止し、画面を確認して再開位置を決める。

セッション確立の再送で実行履歴を消さない。新規セッションへの切り替えは進行中の操作を打ち切って解放を試みた後に行い、古い命令を受け付けない。番号は同一セッション内で再利用せず、上限到達前に未確定操作のない状態でセッションを更新する。

### 異常時の解放

押下時間には上限を設け、PC との通信が切れても Arduino 自身が対象ボタンを解放する。通常完了では対象ボタンだけを解放し、起動時・異常停止時・セッション終了時は復旧処理として全ボタンの解放とスティックなどの中立化を行う。

USB切断などで解放を伝えられない場合は、Switch 側の解放成功を保証しない。PC 側でも成功扱いで周回を継続しない。

### 実装時に確定する詳細

- CRCの方式・対象バイト列、フィールドの書式、最大長、プロトコルのバージョン識別。
- セッションIDの生成・確立手順、番号の範囲、古い通信を混入させない再同期手順。
- 受信期限、応答待ち期限、再送回数、操作全体の期限、押下時間の上限。
- USBライブラリの送信結果と `DONE` の保証範囲、送信失敗時の復旧方法。
- ボタン以外の既存操作（方向キー・スティック）の完了条件と、既に押下中の対象を指定した場合の扱い。
- PC とファームウェアの更新・互換性確認。対応しない方式を検出した場合は操作を開始しない。
