# コントローラー通信プロトコルの信頼性設計

本書は通信方式の設計方針を示す。現在の実装と残課題は末尾を参照する。

## 前提・対象範囲

```text
PC ── USB ── SH-U09C ── UART ── Arduino Micro ── USB ── Switch
```

- PC は SH-U09C と Arduino を一つの入力システムとして扱う。Arduino は指定された入力状態の再現に徹し、操作順・押下時間・リトライ・ゲームの復旧は PC が管理する。
- 通信は Arduino の `Serial1` を使う 115200 bps のシリアル通信。改行区切りのテキスト形式を継続する。
- 配線・電圧設定は [配線・接続手順](../controller/switch_arduino_micro/README.md#sh-u09c-と-arduino-の配線)、書き込みは [Windows からの書き込み手順](windows-arduino-upload.md) を参照する。
- 旧方式のファームウェアは `PING/PONG`、操作名と `OK/ERR` を使い、ボタンの押下時間150msを Arduino 内で管理していた。本書の方式はこれを置き換え、押下時間150msは PC 側の初期値として引き継ぐ。
- 入力状態の設定と Switch 上での操作反映は別の判定とする。ゲーム状態の確認はキャプチャー画像などを使う PC 側の処理が担当する。

## 目的

通信の破損・欠落・切断により、要求や応答が届かない場合がある。「ボタンを1回押す」という操作を単純に再送すると、応答だけが失われた場合に二重操作につながる。

入力状態全体を指定する方式により、同じ状態の再送で不要な押し直しを起こさず、Arduino に操作履歴やゲームの復旧判断を持たせない。同時押しや、移動入力を維持しながら別のボタンを操作する用途も同じ方式で扱う。通信断では入力を解除し、PC が復旧を制御する。物理的な通信不良の原因調査・修復は別途必要である。

## 信頼性設計

### 責務と状態指定

| PC | Arduino |
| --- | --- |
| ボタン・方向キー・スティックの入力状態全体を組み立てる | 要求を検証し、指定状態をUSBレポートに反映する |
| 押下時間・操作順を管理する | 指定状態を維持し、設定結果を返す |
| 応答期限・再送・再接続・ゲーム復旧を管理する | 状態確認に応答し、リース切れでは全入力を解除する |

状態の更新は PC 側で直列化し、応答を確認して次の更新へ進む。複数のボタンやスティックを一つの状態に含め、同時入力を表現する。

```text
PC → Arduino：移動上＋Aの状態を設定
Arduino → PC：設定完了
PC：150ms待つ
PC → Arduino：移動上のみの状態を設定
Arduino → PC：設定完了
```

通常の解放では、PC が対象ボタンだけを除いた状態を送る。他の入力は維持する。Arduino は同じ状態を受信しても、一旦解除して押し直す処理を行わない。操作履歴や完了結果のキャッシュによる重複排除は行わない。

### メッセージの検証と応答

要求・応答にセッションID、要求番号、CRCを付ける。要求には入力状態全体、応答には設定結果またはエラー理由を含める。具体的な書式は「実装状況」を参照する。

Arduino は長さ、CRC、要求種別、値の範囲を検証してから状態を設定する。不正なデータでは入力状態を変更しない。途中で切れた行には受信期限を設け、長すぎる行とともに破棄して改行境界に再同期する。破棄した断片を新しい要求として実行しない。

番号を信用できない破損データは破棄し、検証済みの要求に値の不正などがあれば拒否理由を返す。PC もCRC・セッション・要求番号を照合し、空行、不完全な応答、破損や対応しない応答を成功とみなさない。CRCは偶発的な破損検出用であり、認証機能ではない。

`APPLIED` は指定状態について USB ライブラリの送信関数が成功を返したことを示す。ボタンの解放やゲームでの反映完了は意味しない。送信に失敗した場合はエラーを返し、中立にして復旧待ちに入る。

### PC 側のタイムアウトと再送

PC が応答期限と再送を管理し、Arduino は自律的に操作や応答の再送を行わない。応答が届かない、または期限内に有効な応答がそろわない場合、PC はタイムアウトとして同じセッション・要求番号・入力状態を上限付きで再送する。明示的なエラーは理由に応じて再送または復旧へ振り分け、形式・値の不正は同じ内容で再送しない。

同じ状態の再設定により通常の再送を成立させる。要求番号は応答の対応付けと古い状態への巻き戻り防止に使う。Arduino は最低限の通信状態として最新の受理番号を保持し、古い番号を拒否する。同じ番号では同じ内容だけを受け付ける。これは操作履歴の保存とは区別する。

応答待ち・再送全体には上限を設け、超過したら通常の操作列から PC 側の復旧処理へ移る。結果不明を未実行とみなして新しい番号で同じ操作列をやり直さない。

### 押下時間の精度

PC が押下時間を管理するため、実際の押下時間には次のずれが乗る。PC の時間管理では厳密な実押下時間を保証しない。

- 正常時：往復の通信時間、USBシリアル変換のバッファリング、OS のスケジューリングによる遅れ。
- 異常時：解放の要求が再送になった分の遅れ。上限は1要求の再送全体の時間。
- 解放の要求が届かない場合：リース切れまで押されたままになる。

ずれの許容範囲は入力の種類ごとに定める。ボタンは押下が1回として認識されれば足りるため、延びても影響が小さい。移動入力は延びた分だけ移動距離が変わるため、許容範囲を厳しく設定する。応答期限・再送回数は、この許容範囲に収まるよう決める。

状態指定に「最大保持時間」を付け、超過したら Arduino が中立に戻す方式も検討した。バージョン1では採用せず、押しっぱなしの上限はリース期間とする。Arduino が時間で入力を変えると「指定状態の再現に徹する」責務から外れ、リースと二重の期限管理になるためである。移動のずれが周回に影響すると実機で確認できた場合に再検討する。

### 期限の不変条件

応答期限・再送回数・更新間隔・リース期間の具体値は実機で調整する。ただし調整後も次の関係を満たさなければならない。

```text
応答期限 > Arduino 側の最悪処理時間（USB送信の待ちを含む）
1要求の再送全体 = 応答期限 × 送信回数
リース期間 > 更新間隔 + 1要求の再送全体
リース期間 ≦ ゲーム上許容できる押しっぱなし時間
接続時の再試行全体 > リース期間
```

- 1行目を満たさないと、Arduino がエラー理由を返す前に PC がタイムアウトし、原因を切り分けられない。いずれも停止するため安全側ではある。
- 3行目を満たさないと、リース更新の応答が1回失われただけでリースが切れる。
- 4行目は、解放の要求が届かない場合に押されたままになる時間の上限がリース期間であることによる。リース期間は通信の都合だけでなく、ゲーム上の影響からも決める。
- 5行目は、PC プロセスだけが再起動した場合に古いセッションのリース切れを待つために必要である（「セッションの状態遷移」を参照）。

AVR コアの USB 送信は、ホストが受け取らない場合に一定時間待ってから失敗を返す。この間、Arduino はシリアル受信と期限監視を行えない。最悪時間は実機で確認し、1行目の条件に反映する。

### リースと復旧状態

PC が定期的にリースを更新し、Arduino は期限内だけ入力を維持する。更新は正常なセッションの検証済み要求だけで行い、PC が押下時間を待つ間や、人の確認待ちなど入力のない長い待機の間も更新を継続する。Arduino は USB 送信の待ちを除き、時間待ちで通信や期限監視をブロックしない。

リース切れでは全ボタンを解放し、方向キー・スティックを中立にして復旧待ちに入る。再起動時も中立状態から開始する。以前の入力は自動復元しない。USB切断などで解除を伝えられない場合、Switch 側での解放成功は保証しない。

PC は状態確認によって次を判別できるようにする。通知を一度送るだけにせず、復旧が明示されるまで状態を保持する。

| 状態 | PC の扱い |
| --- | --- |
| 有効なセッションで通常動作中 | 状態更新・同じ状態の再送を継続できる |
| 起動後のセッション未確立 | セッションを確立し、必要な復旧処理へ進む |
| リース切れによる復旧待ち | 古い入力を再送せず、下記の区別に従って続行または復旧処理へ進む |

再起動・リース切れ後に押下状態を送ると、新しい押下になる可能性がある。このため古いセッションの状態指定やリース更新では復旧待ちを解除しない。新しいセッションを中立状態で確立してから、PC が続行やゲームのリセットなどを判断する。

PC はリース切れ・再起動の前後で失われた入力があったかを、自身の記録から次のように区別する。

| PC の記録 | 判断 | PC の扱い |
| --- | --- | --- |
| 最後に `APPLIED` を確認した状態が中立で、応答待ちの状態指定がない | 解除された入力はない | 新しいセッションを確立して操作列を続行してよい |
| 最後に確認した状態が中立以外 | 入力が途中で解除された | 結果不明として復旧処理へ進む |
| 応答待ちの状態指定がある | 結果不明 | 復旧処理へ進む |

これにより、人の確認待ちやゲームの読み込み待ちなど、入力のない待機中に PC の一時停止やUSBの瞬断が起きても、周回を止めずに続行できる。

Arduino にゲームのリセット手順は持たせない。PC は復旧を自動化できるが、復旧にも上限を設け、回復できなければ周回を停止する。

### セッションの状態遷移

セッションIDは PC が生成する。Arduino は次の規則でセッションを引き継ぐ。

- 同じIDのセッション確立は状態を変えない。応答が失われた確立要求の再送で、稼働中の入力を初期化しないためである。
- 稼働中に別のIDの確立要求が来た場合は拒否する。別のセッションから稼働中の入力を中立化させないためである。PC プロセスだけが再起動した場合は、古いセッションのリースが切れるまで待ってから確立する。
- リース切れ・USB エラーで終了したセッションIDでは再確立できない。続行する場合も PC は新しいIDを生成する。

状態ごとの Arduino の動作は次のとおりである。CRC や形式が不正な要求には応答しない。

| イベント | 未確立（`READY`） | 通常動作中（`ACTIVE`） | 復旧待ち（`EXPIRED`） |
| --- | --- | --- | --- |
| 確立（新しいID） | 中立でセッション開始し `ACTIVE` へ | 拒否（`SESSION`） | 中立でセッション開始し `ACTIVE` へ |
| 確立（同じID） | ― | 状態を変えずに `ACTIVE` を返す | ― |
| 確立（終了したID） | ― | ― | 拒否（`SESSION`） |
| 状態指定（同じID） | 拒否（`SESSION`） | 検証して設定。USB エラーなら中立にして `EXPIRED` へ | 拒否（`SESSION`） |
| リース更新（同じID） | 拒否（`SESSION`） | リースを更新 | 拒否（`SESSION`） |
| 別のIDの状態指定・リース更新 | 拒否（`SESSION`） | 拒否（`SESSION`） | 拒否（`SESSION`） |
| 状態確認 | `READY` を返す | `ACTIVE` を返す | `EXPIRED` を返す |
| リース切れ | ― | 中立にして `EXPIRED` へ | ― |
| 再起動 | 中立で `READY` へ | 中立で `READY` へ | 中立で `READY` へ |

`SESSION` の拒否からは、リース切れと別セッションの稼働中を区別できない。PC は `SESSION` を受け取ったら状態確認で現在の状態を確かめてから、続行・待機・復旧を判断する。

### 未確定事項

- 期限の不変条件を満たす応答期限・再送回数・更新間隔・リース期間の値。根拠は実機確認で得る。
- USB 送信が失敗するまでの最悪時間。
- 入力の種類ごとの押下時間の許容範囲。
- PC 側の復旧手順と上限。
- リース切れ後に続行する処理の実装（「実装状況」を参照）。

## 実装状況（バージョン 1）

PC と Arduino は同時に更新する。旧 `PING/PONG` 方式とは互換性がなく、旧ファームウェアでは接続を開始できない。

- ASCII の `1,セッション,番号,操作[,値...],CRC\n`。CRC は末尾の区切りと CRC 自体を除く文字列に対する CRC-16/CCITT-FALSE、4桁の大文字16進数。応答は `1,セッション,番号,操作,結果,CRC\n`。最大128バイト。
- `HELLO` はセッション確立、`STATUS` は状態確認、`KEEP` はリース更新、`SET` は状態指定。動作は「セッションの状態遷移」の表のとおり。
- `SET` はボタンの16ビット整数、方向（0〜7、中立8）、4軸（0〜255）を指定する。要求番号の巻き戻しと同じ番号の異なる状態を拒否する。
- リースは2秒、更新間隔は0.4秒、応答期限は0.35秒。部分行は0.5秒で破棄し改行まで再同期する。PC は各要求を最大3回送る。接続時は `SESSION` 拒否に対して0.5秒間隔で最大6回確立を試みる。期限は暫定値であり実機での調整が必要。
- `APPLIED` は USB ライブラリの送信関数が成功を返したことを示し、Switch やゲームでの反映を保証しない。USB エラーやリース切れでは中立を送信して復旧待ちに入り、PC は操作を停止する。
- リース切れ後に続行する処理と、自動的なゲーム復旧は実装していない。通信異常時は入力の有無にかかわらず結果不明として停止し、状況を確認してから新たに開始する。Arduino の再起動後は以前の入力を復元しない。

実機での通信断、USB 切断、リース期限およびゲーム側の操作反映は未検証。
