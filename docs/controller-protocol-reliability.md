# コントローラー通信プロトコルの信頼性設計

本書は実装予定の設計方針を示す。以下の仕組みは現行プロトコルに未実装である。

## 前提・対象範囲

```text
PC ── USB ── SH-U09C ── UART ── Arduino Micro ── USB ── Switch
```

- PC は SH-U09C と Arduino を一つの入力システムとして扱う。Arduino は指定された入力状態の再現に徹し、操作順・押下時間・リトライ・ゲームの復旧は PC が管理する。
- 通信は Arduino の `Serial1` を使う 115200 bps のシリアル通信。改行区切りのテキスト形式を継続する。
- 配線・電圧設定は [配線・接続手順](../controller/switch_arduino_micro/README.md#sh-u09c-と-arduino-の配線)、書き込みは [Windows からの書き込み手順](windows-arduino-upload.md) を参照する。
- [現行ファームウェア](../controller/switch_arduino_micro/switch_arduino_micro.ino) は `PING/PONG`、操作名と `OK/ERR` を使用する。通常のボタン押下時間150msは PC 側の初期値として引き継ぐ。
- 入力状態の設定と Switch 上での操作反映は別の判定とする。ゲーム状態の確認はキャプチャー画像などを使う PC 側の処理が担当する。

## 目的

通信の破損・欠落・切断により、要求や応答が届かない場合がある。「ボタンを1回押す」という操作を単純に再送すると、応答だけが失われた場合に二重操作につながる。

入力状態全体を指定する方式により、同じ状態の再送で不要な押し直しを起こさず、Arduino に操作履歴やゲームの復旧判断を持たせない。同時押しや、移動入力を維持しながら別のボタンを操作する用途も同じ方式で扱う。通信断では入力を解除し、PC が復旧を制御する。物理的な通信不良の原因調査・修復は別途必要である。

## 信頼性設計

### 責務と状態指定

| PC | Arduino |
| --- | --- |
| ボタン・方向キー・スティックの入力状態全体を組み立てる | 要求を検証し、指定状態をUSBレポートに反映する |
| 押下時間・操作順を管理する | 指定状態を維持し、設定結果を返す |
| 応答期限・再送・再接続・ゲーム復旧を管理する | 状態確認に応答し、リース切れでは全入力を解除する |

状態の更新は PC 側で直列化し、応答を確認して次の更新へ進む。複数のボタンやスティックを一つの状態に含め、同時入力を表現する。

```text
PC → Arduino：移動上＋Aの状態を設定
Arduino → PC：設定完了
PC：150ms待つ
PC → Arduino：移動上のみの状態を設定
Arduino → PC：設定完了
```

通常の解放では、PC が対象ボタンだけを除いた状態を送る。他の入力は維持する。Arduino は同じ状態を受信しても、一旦解除して押し直す処理を行わない。操作履歴や完了結果のキャッシュによる重複排除は行わない。

### メッセージの検証と応答

要求・応答にセッションID、要求番号、CRCを付ける。要求には入力状態全体、応答には設定結果またはエラー理由を含める。以下は概念例であり、実際のフィールド形式とCRC値は省略している。

```text
SET_STATE,<session>,42,<buttons>,<hat>,<sticks>,<CRC>\n
RESULT,<session>,42,APPLIED,<CRC>\n
```

Arduino は長さ、CRC、要求種別、値の範囲を検証してから状態を設定する。不正なデータでは入力状態を変更しない。途中で切れた行には受信期限を設け、長すぎる行とともに破棄して改行境界に再同期する。破棄した断片を新しい要求として実行しない。

番号を信用できない破損データは破棄し、検証済みの要求に値の不正などがあれば拒否理由を返す。PC もCRC・セッション・要求番号を照合し、空行、不完全な応答、破損や対応しない応答を成功とみなさない。CRCは偶発的な破損検出用であり、認証機能ではない。

`APPLIED` は指定状態について所定のUSB送信処理が完了したことを示す。ボタンの解放やゲームでの反映完了は意味しない。送信結果を確認し、失敗時はエラーを返す。ライブラリがキュー登録までしか保証しない場合は、応答の保証範囲もそこまでとする。具体的な保証範囲は実装前に調査する。

### PC 側のタイムアウトと再送

PC が応答期限と再送を管理し、Arduino は自律的に操作や応答の再送を行わない。応答が届かない、または期限内に有効な応答がそろわない場合、PC はタイムアウトとして同じセッション・要求番号・入力状態を上限付きで再送する。明示的なエラーは理由に応じて再送または復旧へ振り分け、形式・値の不正は同じ内容で再送しない。

同じ状態の再設定により通常の再送を成立させる。要求番号は応答の対応付けと古い状態への巻き戻り防止に使う。Arduino は最低限の通信状態として最新の受理番号を保持し、古い番号を拒否する。同じ番号では同じ内容だけを受け付ける。これは操作履歴の保存とは区別する。

再送中は押下時間が延びる可能性がある。PC の時間管理では厳密な実押下時間を保証しない。応答待ち・再送全体には上限を設け、超過したら通常の操作列から PC 側の復旧処理へ移る。結果不明を未実行とみなして新しい番号で同じ操作列をやり直さない。

### リースと復旧状態

PC が定期的にリースを更新し、Arduino は期限内だけ入力を維持する。更新は正常なセッションの検証済み要求だけで行い、PC が押下時間を待つ間も更新を継続する。Arduino は時間待ちで通信や期限監視をブロックしない。

リース切れでは全ボタンを解放し、方向キー・スティックを中立にして復旧待ちに入る。再起動時も中立状態から開始する。以前の入力は自動復元しない。USB切断などで解除を伝えられない場合、Switch 側での解放成功は保証しない。

PC は状態確認によって次を判別できるようにする。通知を一度送るだけにせず、復旧が明示されるまで状態を保持する。

| 状態 | PC の扱い |
| --- | --- |
| 有効なセッションで通常動作中 | 状態更新・同じ状態の再送を継続できる |
| 起動後のセッション未確立 | セッションを確立し、必要な復旧処理へ進む |
| リース切れによる復旧待ち | 古い入力を再送せず、復旧処理へ進む |

再起動・リース切れ後に押下状態を送ると、新しい押下になる可能性がある。このため古いセッションの状態指定やリース更新では復旧待ちを解除しない。新しいセッションを中立状態で確立してから PC がゲームのリセットなどを判断する。セッション確立の再送でも、稼働中の入力や復旧状態を意図せず初期化しない。

Arduino にゲームのリセット手順は持たせない。PC は復旧を自動化できるが、復旧にも上限を設け、回復できなければ周回を停止する。

### 実装時に確定する詳細

- 状態・状態確認・セッション確立・リース更新の書式、CRCの方式と対象範囲、最大長、バージョン識別。
- セッションIDの生成と確立手順、要求番号の範囲・更新規則、古い通信を排除する再同期手順。
- 応答期限、再送間隔・回数、リース期間・更新間隔。固定値の根拠は実機確認で得る。
- USBライブラリの送信結果と `APPLIED` の保証範囲、エラー理由の分類。
- PC 側の状態更新とリース更新の調停、押下時間の計測起点、復旧手順と上限。
- PC とファームウェアの互換性確認。対応しない方式では操作を開始しない。
